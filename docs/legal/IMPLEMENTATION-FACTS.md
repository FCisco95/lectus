# Lectus implementation facts for legal and release review

Reviewed: 2026-10-21. Source baseline: commit `97d1ade5ddc37c4eecc86d184ad02904ed64609e` plus the shared working tree. This is an engineering evidence inventory, not a privacy notice, contract, release receipt or compliance opinion. The translation, onboarding and legal gates are being implemented concurrently; the final candidate must be rechecked before publishing these facts as user-facing promises. No real user files, credentials, accounts or installed application were inspected for this audit.

## Storage and recipient boundaries

`Config::app_support_dir` resolves `%APPDATA%/ai.organic.lectus` on Windows and `~/Library/Application Support/ai.organic.lectus` on macOS. History/license/model paths use Tauri's app-data directory with the `ai.organic.lectus` identifier. Verify paths and uninstall behavior in the actual installer.

| Local item | Content | Protection/retention supported by inspected code |
|---|---|---|
| `config.json` | Preferences, API key, provider URL/model IDs, display-name override, vocabulary/rules/profiles | JSON serialization to disk; no OS keychain encryption shown. Retained until changed/deleted. |
| `history.json` | Up to 500 ordinary transcripts and metadata | JSON, clear/eviction; no time-based expiry or encryption shown. |
| `license.json` | Wallet address and cached membership facts | JSON; unlink attempts deletion. Public blockchain data remains on-chain. |
| `remote-dictation.json` / `api.json` | Pairing shared secrets / local API bearer token and settings | JSON; Unix mode 0600 at creation. Do not promise encryption at rest or guaranteed Windows ACL isolation without verification. |
| `models/`, `.part`, `whats_new.json` | Downloaded models, partial files, release notes | No ordinary UI model deletion flow was established. Release notes are removed on read. |

Configured provider endpoints are user-controlled. The model-list check restricts remote URLs to HTTPS, but the inspected speech/chat clients themselves construct requests from the configured URL. Do not promise universal transport encryption for arbitrary provider configuration without checking the final save/runtime validation. Normal HTTP connections to a deliberately configured local provider are a separate case.

Publisher access to the public GitHub release repository, support submissions, billing/marketing sites and account dashboards is outside this code audit. Publisher identity, controller/processor roles, intended countries, support mailbox, actual support practices and provider contractual arrangements remain unknown. A direct client-to-provider architecture does not by itself establish every legal role or exemption.

## Installer/release facts and open proof

At baseline `Cargo.toml` used generic description and `authors = ["you"]`, with no application license field. The hardening continuation replaced the description and removed that placeholder author without inventing a publisher. First-party licensing and publisher decisions remain open. Draft legal resources are now present, but are not final legal approval.

Windows resource configuration bundles llama/ggml DLLs and backend DLLs; macOS bundles related dylibs/backends and requires microphone/local-network descriptions. The release workflow supplies Tauri updater-signing secrets and produces draft releases. This does not establish Windows Authenticode publisher identity or Apple Developer ID/notarization. No such signing configuration was observed in the baseline workflow; keys/accounts were not inspected. WebView2 bootstrap/runtime, OpenMP/Vulkan redistributables, uninstall persistence, upgrade/downgrade behavior and final embedded notices require installer-level verification.

Existing icons/brand mark and system-font selection were observed. Ownership/provenance of artwork, the Lectus/Organic names and other marks was not established. No remote font download was found in the CSS inspected.

See [RELEASE-CHECKLIST.md](RELEASE-CHECKLIST.md) for decision owners, legal applicability questions and evidence needed before a public release.

## Same-session implementation update (source review, final runtime receipt separate)

The new `legal.rs` exposes document readiness and version/hash-bound Terms acceptance. Draft documents cannot be accepted; new setup completion calls `ensure_accepted`. The microphone restart path now checks onboarding completion and whether published current Terms require acceptance. The generic-config bypass finding (`incoming.onboarding_completed` could previously promote false to true) was sent to the backend owner for correction and a regression test; verify the final implementation before calling the gate closed.

A new `cloud_processing_acknowledged` flag defaults false, is reset when provider URL changes, and gates cloud speech credentials plus cloud chat generation. This is a processing-choice mechanism, not a finding that any particular legal basis is sufficient. Tests inspected cover unacknowledged cloud translation making no request and offline translation never falling back to available cloud credentials; test execution remains in the parent native-verification receipt. A separate Claude/CLI acknowledgement is being integrated and requires final verification.

New history fields preserve pre-translation source text/language and translation error alongside final text. On ordinary translation failure the current pipeline records source/error and returns before insertion; on success it records both source and translated output. The source snapshot is taken after optional cleanup, so it is not necessarily the verbatim raw recognition result. Retention remains count-limited and local JSON.

Third-party collection completed: 685 all-target Cargo packages, 134 npm lock entries, 1,218 exact copied license/NOTICE files. `missing-notices.json` lists 67 Cargo packages and four installed npm build-native packages without standalone notice files, plus 59 optional npm platform packages absent on this machine. These are unresolved inventory entries, not 130 established violations or missing runtime packages. An offline repeat produced the same inventory SHA256 (`508b1063bcb144d0179c8c84ca053bb687657db1d105e1efc84d5fc7bf22d630`); all 1,218 copied-file hashes matched the inventory. Full official Gemma HTML snapshots are accompanied by derived offline-readable text; only the original snapshots are byte-identical source copies. Final bundle inclusion and corresponding-source duties still need reconciliation.

## Optional Gemma agreement implementation

`src-tauri/src/model_license.rs` now provides a separate local, content-bound Gemma agreement receipt. The original official HTML is preserved under `legal/third-party/models/gemma-3/`; `scripts/extract-model-agreements.py` derives the bundled readable documents and provenance under `legal/model-agreements/`. Explicit acceptance is required before downloading or admitting local Gemma cleanup, including reuse of a resident model. Revocation affects later admissions, retains the model file and does not change cloud choices. Qwen translation has its own model terms and is not gated by the Gemma receipt. No actual agreement was accepted during fixture verification. See `docs/reviews/2026-10-21-license-history-hardening.md` and the model-license UI report for test scope. This mechanism does not resolve all distribution conditions or legal review.
